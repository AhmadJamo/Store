# Stock transfers
> Status: IMPLEMENTED | Last reviewed: 2026-10-04

Workflow: Draft → Submitted → Approved → Posted; submitted transfers can be rejected then returned to draft; posted transfers can be cancelled, which makes compensating stock movements. Creator cannot approve own transfer. Post creates out/in stock transactions and adjusts both warehouse balances in UnitOfWork. For tracked products, posting chooses lot/serial identities by the source warehouse's configured removal strategy, moves them between the selected positions and cancellation reverses that same route with balanced trace entries. A StockTransfer rowversion prevents two concurrent workflow transitions, including duplicate posting, from both committing.

Source and destination locations are optional per line. A specified location must belong to its matching warehouse. Posting moves exact location balances when supplied; omitted destination locations create unassigned destination stock, while omitted sources may consume only unassigned source stock. Creation generates its tenant StockTransfer `DocumentSequence` inside the same transaction; a missing row receives a safe default, so configuration absence no longer blocks creation. Sources: StockTransfer/Item/History/status/action entities; transfer commands and DTOs; interface/service/repository/configurations and transfer screens.

Warehouse policy can require an exact source or destination for structured warehouses. Simple warehouses reject exact locations and transfer only their warehouse-level balance. Destination capacity is checked during posting when capacity enforcement is enabled.

Draft lines may persist an optional `LOT:QUANTITY` or one-serial-per-line identity selection. Posting validates the selection against the exact source position and records `Manual` on both trace legs; an empty selection uses the source warehouse strategy. Cancellation reconstructs the original positive destination trace and returns those exact identities instead of running a new automatic allocation. Migration `AddTransferTrackingAllocations` adds the nullable draft field without modifying historic transfers.

Reviewed replenishment suggestions may create a Draft transfer through the normal `StockTransferService`. The action requires both replenishment-management and transfer-create permissions, revalidates availability and warehouse/location policy, and uses a neutral `REPLENISHMENT:RULE:{id}` reference to prevent a second open intent. No workflow transition occurs automatically.
## WMS-030 movement integration
Each newly approved transfer creates three Planned physical stages per line: outbound from the source, transit between warehouses and inbound to the destination. The existing Post action still performs the complete atomic stock and valuation transfer and now posts those stages. Cancellation reverses existing balances/StockTransactions and marks linked stages Reversed. Tenant-safe source-document/line/stage uniqueness prevents duplicate plans. Historic transfers are not backfilled, and compatibility fallbacks preserve posting/cancellation of records created before this feature.
