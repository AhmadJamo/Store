# تدقيق UI/UX — baseline V3.0

## نقاط قوة مثبتة

- shell موحد، persistent tabs، breadcrumbs، command search، localization عربي/إنجليزي وRTL.
- shared page headers, feedback states, form error summaries وAPI recovery.
- صفحة المستودعات تحوي نموذجًا فعليًا وصلاحيات مستقلة وتحافظ على البيانات عند فشل الحفظ.
- POS الحالي يدعم touch profile، scan/search واختصارات أساسية.

## فجوات مثبتة

1. `/branches`: لا CTA لإنشاء فرع ولا نموذج تعديل/تعطيل؛ الإنشاء موجود في صفحة Catalog Masters غير المتوقعة للمستخدم.
2. فصل المعلومات: إعداد الوصول والمستودعات/terminals ظاهر، لكن lifecycle الأساسي للفرع غير قابل للإدارة من مكانه الطبيعي.
3. وثائق الحالة المتعارضة تجعل توقعات المنتج غير واضحة.
4. بعض الميزات مكتوبة في مكونات شديدة التكثيف كسطر واحد؛ هذا ليس خطأ runtime لكنه يرفع كلفة المراجعة. لا يُعاد تقسيمها بلا فائدة feature-based.
5. لا يوجد بعد دليل acceptance لكل 196 مسار؛ حالات العرض وحدها لا تكفي.

## معيار الموجة الأولى

وضوح الإجراء الرئيسي، أقل عدد نقرات، validation قرب الحقول وsummary، حفظ المدخلات عند الخطأ، إخفاء الإجراءات غير المصرح بها، keyboard/RTL/responsive، وربط success بالنتيجة الفعلية.

## REC-003 route discoverability evidence — 2026-11-17

المصفوفة المولدة تغطي 196 مسار شاشة. لا توجد فجوة P1 بين API literals والـControllers في المحاسبة أو المبيعات أو المخزون. Module hubs والصفحات العرضية تبقى مصنفة Presentation-only للمراجعة اليدوية، ولا تُعامل الشاشة الظاهرة وحدها كدليل اكتمال وظيفي.
