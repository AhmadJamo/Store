# خارطة الطريق الرئيسية الوحيدة / Master Roadmap

> هذه الوثيقة ترتب الأولوية فقط. الخطط التخصصية تبقى تفاصيل، ولا تبدأ مهمة دون أن تكون في `NEXT_TASK.md`.

## P0 — مخاطر حرجة

### `P0-SEC-001` — إغلاق أثر بيانات دخول المسؤول التاريخية

> COMPLETED 2026-10-15 (مكتملة ضمن النطاق التجريبي المحلي المعلن). راجع
> [دليل الإغلاق](operations/P0-SEC-001-CREDENTIAL-CLOSURE.md).

- الهدف/السبب: إثبات أن السر المنشور سابقًا لا يعمل في أي بيئة.
- إعادة الاستخدام: إعداد bootstrap الآمن والقفل الحاليان.
- الملفات المحتملة: لا كود متوقع؛ سجل تشغيل آمن و`06_SECURITY.md` وملفات التحكم.
- الاعتماد: مالك كل بيئة وصلاحية الهوية.
- القبول: جرد البيئات، تدوير السر، إبطال الجلسات، فشل السر القديم، دليل موقع دون أسرار.
- الاختبارات: تسجيل دخول سلبي، مراجعة الجلسات والحسابات المميزة.
- الترحيل/الرجوع: لا مخطط؛ rollback بإجراء break-glass موثق لا بإعادة السر القديم.
- التعقيد: متوسط تشغيليًا.

### `P0-OPS-002` — النسخ الاحتياطي واختبار الاستعادة

> NEXT PROPOSED TASK (المهمة التالية المقترحة؛ تنتظر الموافقة).

- الهدف/السبب: منع فقد البيانات وإثبات الاستعادة.
- إعادة الاستخدام: تقارير المصالحة الحالية واختبار SQL.
- الملفات المحتملة: runbook تشغيل، أدلة بيئة، ملفات project-control؛ لا كود أولًا.
- الاعتماد: SEC-001، مالك SQL والاستضافة.
- القبول: RPO/RTO معتمدان، نسخة مشفرة، استعادة معزولة، مطابقة الشركات/القيود/المخزون/outbox.
- الاختبارات: restore drill وreconciliation.
- الترحيل/الرجوع: لا ترحيل؛ حذف البيئة المعزولة وفق سياسة آمنة.
- التعقيد: عالٍ تشغيليًا.

### `P0-DB-003` — مطابقة إصدار مخطط كل بيئة

- الهدف/السبب: إزالة عدم اليقين حول 112 ترحيلًا.
- إعادة الاستخدام: `__EFMigrationsHistory` ولقطة EF.
- الملفات المحتملة: `03_DATABASE.md`, سجل البيئة، لا تعديل ترحيلات.
- الاعتماد: OPS-002 قبل أي إصلاح.
- القبول: قائمة البيئة→آخر ترحيل→فروق→خطة forward-fix.
- الاختبارات: dry-run على نسخة مستعادة وبناء النموذج.
- الترحيل/الرجوع: لا تغيير في مرحلة الاكتشاف.
- التعقيد: متوسط.

## P1 — الأساسات اللازمة

### `P1-AUD-010` — تصميم تدقيق أمني/تشغيلي قابل للتحقيق

- الهدف: correlation/outcome/reason/redaction/retention دون نسخ القيود.
- إعادة الاستخدام: `AuditLog`, histories, supplier external audit.
- الملفات المحتملة: Domain/Application/Infrastructure/Security docs واختبارات.
- الاعتماد: OPS-002 وقرار احتفاظ.
- القبول: ADR ونموذج تهديد وترحيل إضافي وخطة rollback قبل الكود.
- الاختبارات: transaction rollback، تنقيح، عزل، ترتيب، وصول.
- أثر الترحيل: إضافي فقط؛ dual-read عند الحاجة.
- التعقيد: عالٍ.

### `P1-OBS-020` — خط بناء ومراقبة وقياس أداء

- الهدف: نتائج قابلة للتكرار بدل تشغيل محلي يدوي.
- إعادة الاستخدام: مشروعا الاختبار الحاليان والسجلات.
- الملفات المحتملة: CI، health/telemetry config، runbooks.
- الاعتماد: بيئة اختبار معزولة وإدارة أسرار.
- القبول: build+748+SQL gates، تنبيه فشل، workload موثق وp95/p99.
- الاختبارات: pipeline failure, soak, deadlock/connection metrics.
- الترحيل: لا مخطط مبدئيًا؛ rollback بإزالة instrumentation flag.
- التعقيد: عالٍ.

### `P1-ARC-030` — توحيد حدود الاستعلام والمعاملة تدريجيًا

- الهدف: منع controller→repository وحفظ المستودع غير المتجانس.
- إعادة الاستخدام: خدمات التطبيق وUnitOfWork الحالية.
- الملفات المحتملة: المتحكم/الخدمة/DTO/المستودع للوحدة التي تُلمس فقط.
- الاعتماد: اختبارات الوحدة المستهدفة.
- القبول: لا تغير سلوك، DTO مسقط، pagination، معاملة واحدة.
- الاختبارات: regression، tenant، failure-midway.
- الترحيل: غالبًا لا؛ rollback للكود فقط.
- التعقيد: متوسط لكل شريحة.

## P2 — إكمال دورات ERP الحالية

### `P2-CUS-040` — اعتماد `CUS-005` ثم ملف الزبون `CUS-010`

- الهدف: تأسيس هوية زبون صالحة للمبيعات والذمم.
- إعادة الاستخدام: Customer.Id، نموذج المورد، الصلاحيات والعزل.
- الملفات: موثقة تفصيليًا في خطة الزبائن.
- الاعتماد: قرار BusinessPartner والحساب والأرشفة.
- القبول/الاختبارات/الترحيل: حسب وثيقة الزبائن؛ إضافي ويحفظ المعرفات.
- التعقيد: عالٍ.

### `P2-SAL-050` — تنفيذ `SAL-020..100` بالتسلسل

- الهدف: التسعير→العرض→الطلب→الحجز→التسليم→الفاتورة→الذمم→الدفع→المرتجع.
- إعادة الاستخدام: Sale/POS كمسار قديم، Inventory، Journal، numbering.
- الملفات: محددة في خطة المبيعات.
- الاعتماد: CUS-010 وكل بوابة مرحلة.
- القبول: لا أثر مخزون عند التأكيد، COGS عند التسليم، الفاتورة لا تعني الدفع.
- الاختبارات: concurrency/idempotency/accounting/security/RTL.
- الترحيل: إضافي مع cutover منفصل.
- التعقيد: عالٍ جدًا عبر شرائح صغيرة.

### `P2-WMS-060` — إغلاق بنود WMS المؤجلة

- الهدف: الاستلام الجزئي للنقل وجدولة الجرد وبوابات cutover المتبقية.
- إعادة الاستخدام: movement/balance/reservation/tracking.
- الملفات: خطة WMS.
- الاعتماد: مصالحة صفر وأولوية مالك المنتج.
- القبول: invariants كمية وتزامن وعكس.
- الاختبارات: SQL concurrent + full lifecycle.
- الترحيل: إضافي فقط.
- التعقيد: عالٍ.
