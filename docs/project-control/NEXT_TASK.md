## `P1-AUD-012` — أول تغطية تدقيق دلالية

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

> الاعتماد السابق: اكتمل `P1-AUD-011` وطُبق جدوله الإضافي على Demo مع بقاء الميزة مغلقة والجدول فارغًا. العقد في
> [../AUDIT_SECURITY_ARCHITECTURE_AND_IMPLEMENTATION_PLAN.md](../AUDIT_SECURITY_ARCHITECTURE_AND_IMPLEMENTATION_PLAN.md)
> والقرار في [../decisions/2026-10-15-audit-event-v2-boundary.md](../decisions/2026-10-15-audit-event-v2-boundary.md).

### الهدف

تفعيل أول تغطية دلالية لـ`AuditEvent` (حدث التدقيق) على تغييرات أدوار وصلاحيات الشركة وإعداداتها الحساسة.
يُسجل الحدث داخل نفس حفظ العمل، بمفتاح بصمة خاص ببيئة Demo محفوظ خارج المستودع، ودون إنشاء شاشة قراءة.

### داخل النطاق

- اعتماد أكواد ثابتة لأحداث إنشاء/تعديل/حذف الدور وتغيير صلاحياته.
- تسجيل تغييرات الإعدادات الحساسة التي تملك حفظًا ذريًا واضحًا، دون نسخ القيم السرية أو المستندات.
- إضافة قوائم السماح المطلوبة فقط، مع سبب نصي ممنوع افتراضيًا واستخدام ReasonCode (كود السبب).
- توليد مفتاح Demo عشوائي لا يقل عن 256 بت في User Secrets (أسرار المستخدم) وتفعيل الميزة محليًا فقط.
- ربط CorrelationId (معرّف الترابط) من الطلب، واستخدام OperationId عند وجود إعادة محاولة قابلة للتكرار.
- اختبارات نجاح/rollback، شركتين، تنقيح، تكرار وبصمة، ومصالحة عدد الأحداث المتوقع.

### خارج النطاق

- لا شاشة عرض أو تصدير ولا صلاحيات AuditEvents جديدة بعد.
- لا تغطية المصادقة أو المنصة أو المورد الخارجي؛ هذه في `P1-AUD-013`.
- لا إيقاف أو تعديل أو backfill (تعبئة تاريخية) لسجل `AuditLogs` القديم.
- لا احتفاظ/أرشفة أو checkpoint (نقطة تثبيت) خارجي.
- لا تخزين كلمات مرور أو token (رمز وصول) أو مفتاح البصمة أو بيانات شخصية غير لازمة داخل الحدث.

### القبول

1. كل تغيير معتمد في الدور/الصلاحية أو الإعداد المحدد ينتج حدثًا دلاليًا واحدًا بعد النجاح.
2. فشل أو rollback (رجوع المعاملة) لا يترك حدث نجاح.
3. الحدث يحمل الشركة والمستخدم والترابط والمرجع والنتيجة دون سر أو حمولة خام.
4. شركتان لا تستطيعان قراءة أو اصطناع حدث للأخرى، والمنصة لا تدخل من سياق شركة.
5. مفتاح Demo خارج Git (نظام حفظ الكود)، وله نسخة key version دون كشف قيمته في الدليل.
6. إغلاق feature flag يوقف الكتابة الجديدة ولا يحذف دليلًا سابقًا.
7. البناء واختبارات الأمان وSQL (قاعدة البيانات) ناجحة، والعدد المتوقع للأحداث متطابق.
