## `P1-AUD-010` — تصميم سجل تدقيق أمني وتشغيلي قابل للتحقيق

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

> الاعتماد السابق: تطابق الكود وقاعدة Demo المحلية في 112 ترحيلًا دون انحراف أو تغيير نموذج معلق. الدليل في
> [operations/P0-DB-003-SCHEMA-RECONCILIATION.md](operations/P0-DB-003-SCHEMA-RECONCILIATION.md).

### الهدف

تصميم تطوير آمن لـ`AuditLog` (سجل التدقيق) يوثق من نفّذ العملية، ومتى، وعلى أي شركة وكيان، ونتيجتها وسببها
وترابطها مع الطلب، مع تنقيح الأسرار وسياسة احتفاظ ومقاومة عبث، دون نسخ القيود المالية أو سجلات المجال.

### لماذا هذه الخطوة الآن؟

النواة الأمنية وقاعدة البيانات والاستعادة أصبحت مثبتة محليًا، لكن سجل التدقيق الحالي بسيط ولا يجيب بصورة موثوقة
عن قبل/بعد، النجاح/الفشل، العملية المترابطة أو سبب التجاوز. إضافة ميزات وبيئات قبل تثبيت هذا العقد توسع فجوة
التحقيق والمساءلة.

### المرحلة الأولى المعتمدة عند البدء

هذه مهمة تصميم وقرار فقط قبل الكود:

- جرد `AuditLog` وسجلات التاريخ المتخصصة ومن يكتبها ويقرأها.
- نموذج تهديد وتصنيف أحداث يجب/لا يجب تسجيلها.
- عقد حقول يشمل `CorrelationId` (معرّف الترابط)، النتيجة، السبب، القيم المنقحة وهوية الشركة والمستخدم.
- قرار احتفاظ ووصول وتصدير ومقاومة عبث.
- `ADR` (سجل قرار معماري) وخطة ترحيل إضافية و`rollback` (رجوع) واختبارات.
- منع ازدواج مصدر الحقيقة مع القيود المحاسبية وحركات المخزون وتاريخ المستندات.

### خارج النطاق

- لا كود أو ترحيل أو شاشة في مرحلة التصميم الأولى.
- لا تخزين كلمات مرور أو `token` (رمز وصول) أو بيانات دفع حساسة.
- لا تحويل سجل التدقيق إلى بديل عن قيود المحاسبة أو سجلات المجال.
- لا بدء التنفيذ قبل اعتماد التصميم والحقول وسياسة الاحتفاظ.

### القبول

1. جرد كامل للمصادر الحالية والفجوات.
2. عقد حدث موحد وحدود ملكية واضحة.
3. نموذج تهديد وقواعد تنقيح ووصول واحتفاظ.
4. ADR وخطة مراحل وترحيل ورجوع واختبار.
5. تحديد أول شريحة تنفيذ صغيرة دون تنفيذها.
