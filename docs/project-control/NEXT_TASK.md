## `P1-AUD-016` — مصالحة تغطية التدقيق وتجميد السجل القديم

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

> الاعتماد السابق: اكتمل `P1-AUD-015` بسياسة الاحتفاظ المعتمدة والحجز القانوني ونقطة التثبيت الخارجية
> وأدوار SQL (قاعدة البيانات). دليل التنفيذ في
> [operations/P1-AUD-015-RETENTION-CHECKPOINT.md](operations/P1-AUD-015-RETENTION-CHECKPOINT.md).

### الهدف

إثبات أن العمليات الأمنية والإدارية والمالية الحرجة المشمولة تنتج حدث `AuditEvent` الدلالي المتوقع، ثم وقف
إنشاء صفوف عامة جديدة في `AuditLogs` القديم مع الحفاظ الكامل على تاريخه وإمكانية الرجوع المؤقت.

### داخل النطاق

- جرد ثابت للعمليات الحرجة ونوع الحدث والنتيجة والنطاق المتوقع لكل عملية.
- تقرير مصالحة قابل للإعادة يوضح المتوقع والموجود والفجوات المفسرة دون نسخ تفاصيل مالية أو مخزنية.
- إغلاق فجوات التغطية الحرجة المكتشفة قبل التحويل.
- مفتاح تشغيل مستقل يوقف `AuditSaveChangesInterceptor` للكتابات الجديدة فقط بعد نجاح المصالحة ونقطة تثبيت.
- اختبار رجوع يعيد الكاتب القديم مؤقتًا دون حذف أو تعديل أي تاريخ.

### خارج النطاق

- لا حذف أو backfill (تعبئة تاريخية) لـ`AuditLogs`.
- لا تحويل السجل القديم إلى أحداث دلالية تخمينية.
- لا استبدال لسجلات القيود والحركات والتتبع وتاريخ المستندات المتخصصة.

### القبول

1. تقرير التغطية لا يحتوي فقدًا غير مفسر لأي عملية حرجة معتمدة.
2. إنشاء `AuditLogs` الجديد يتوقف خلف مفتاح رجوع، وتستمر `AuditEvents` دون انقطاع.
3. التاريخ القديم يبقى قابلًا للقراءة ولا يتغير عدده أثناء التحويل.
4. نقطة تثبيت قبل/بعد التحويل، والبناء و768+ فحصًا وSQL ناجحة.
