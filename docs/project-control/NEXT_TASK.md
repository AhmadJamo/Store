## `P0-DB-003` — مطابقة إصدار مخطط قاعدة البيانات

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

> الاعتماد السابق: أُغلقت تجربة النسخ والاستعادة المحلية `P0-OPS-002` في 2026-10-15. الدليل في
> [operations/P0-OPS-002-BACKUP-RESTORE-DRILL.md](operations/P0-OPS-002-BACKUP-RESTORE-DRILL.md).

### الهدف

مقارنة ترحيلات `EF Core` (إطار ربط الكائنات بقاعدة البيانات) الموجودة في الكود مع جدول
`__EFMigrationsHistory` في قاعدة `MiniStoreDb` التجريبية، وتحديد أي ترحيل مفقود أو زائد أو غير متسق دون
تطبيق تغيير على القاعدة الأصلية.

### لماذا هذه الخطوة الآن؟

أصبحت لدينا نسخة مشفرة وتجربة استعادة ناجحة. يمكن الآن إزالة عدم اليقين حول 112 ترحيلًا بأمان، قبل أي تطوير
يضيف مخططًا جديدًا أو ادعاء جاهزية للإنتاج.

### النطاق

- جرد ترحيلات الكود وترحيلات القاعدة وترتيبها.
- تشغيل `EF migrations list` (قائمة الترحيلات) وفحص `has-pending-model-changes` (تغييرات نموذج معلقة).
- مقارنة مخطط الجداول والفهارس والعلاقات الحرجة مع لقطة `EF Core` الحالية.
- تصنيف كل فرق إلى: توثيق قديم، ترحيل غير مطبق، انحراف يدوي أو مشكلة لقطة.
- اقتراح `forward-fix` (إصلاح أمامي) آمن عند وجود فرق، دون تنفيذه في هذه المهمة.

### خارج النطاق

- لا تطبيق ترحيلات على `MiniStoreDb`.
- لا تعديل أو حذف ترحيل قديم.
- لا تعديل مباشر للمخطط أو جدول تاريخ الترحيلات.
- لا بدء ميزة جديدة قبل إصدار نتيجة المطابقة.

### القبول

1. قائمة موثقة لآخر ترحيل في الكود والقاعدة وعدد كل منهما.
2. نتيجة صريحة: متطابق أو قائمة فروق محددة.
3. نتيجة فحص تغييرات النموذج المعلقة.
4. خطة إصلاح أمامي واختبار ورجوع لأي فرق دون تنفيذه.
5. تحديث حالة المشروع والمهمة التالية.

### الاختبارات

- أوامر `dotnet ef` (أداة ترحيلات قاعدة البيانات) للقراءة فقط.
- استعلامات `SQL` (قاعدة البيانات) للقراءة فقط.
- لا يعد نجاح البناء وحده دليل تطابق للمخطط.
