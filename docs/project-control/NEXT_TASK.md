## `P1-AUD-014` — قارئ وتصدير سجل التدقيق المدرك للصلاحيات

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

> الاعتماد السابق: اكتمل `P1-AUD-013` وربط فشل/قفل الدخول والرفض الفعلي وإدارة المنصة ووصول
> تكاملات الموردين بسجل `AuditEvent` (حدث التدقيق). دليل التنفيذ في
> [operations/P1-AUD-013-SECURITY-AUDIT-COVERAGE.md](operations/P1-AUD-013-SECURITY-AUDIT-COVERAGE.md).

### الهدف

إضافة سطح قراءة وبحث وتصدير مقسّم الصفحات لسجل التدقيق، مع فصل صارم بين شركة ومنصة ونظام، وصلاحيات
مستقلة للعرض والتصدير، وتسجيل عملية التصدير نفسها دون كشف الحقول المنقحة أو أي أسرار.

### داخل النطاق

- صلاحيات ثابتة منفصلة لعرض سجل الشركة وتصديره، وسياسات منصة مستقلة للأحداث Platform/System.
- استعلام Application عبر DTO (كائن نقل بيانات) لا يعرض كيان EF مباشرة، مع pagination (تقسيم صفحات) وحدود حجم ثابتة.
- بحث زمني وتصنيف حسب نوع الحدث والنتيجة والممثل والمورد ومعرّف الترابط دون تجاوز نطاق المستخدم.
- شاشة ثنائية اللغة واتجاه RTL للعربية، وتصدير محدود ومسجل كحدث دلالي.
- اختبار عدم تسرب شركة/منصة، وعدم إمكان التصدير بصلاحية العرض وحدها، وعدد الاستعلامات وحجم الصفحة.

### خارج النطاق

- لا تعديل أو حذف لأي `AuditEvent` سابق.
- لا احتفاظ أو أرشفة أو صلاحيات SQL منفصلة أو checkpoint (نقطة تثبيت) خارجي؛ هذه في `P1-AUD-015`.
- لا backfill (تعبئة تاريخية) ولا إيقاف لـ`AuditLogs` القديم؛ المصالحة النهائية في `P1-AUD-016`.
- لا عرض أسرار أو طلبات خام أو قيم أزالها المنقح أصلًا.

### القبول

1. مستخدم الشركة يرى أحداث شركته فقط، والمنصة لا تنتحل شركة والعكس صحيح.
2. العرض والتصدير يحتاجان صلاحيتين منفصلتين مع منع فعلي من الخادم.
3. كل صفحة محدودة ومرتبة ترتيبًا ثابتًا، ولا يوجد تحميل غير محدود.
4. التصدير محدود، منقح، ويكتب حدثًا واحدًا دون تصدير نفسه بصورة متكررة.
5. العربية والإنجليزية وRTL تعمل، والبناء واختبارات الأمان وSQL ناجحة.
