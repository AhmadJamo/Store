# المهمة التالية الوحيدة / Next Task

## `P0-SEC-001` — التحقق من إغلاق أثر بيانات دخول المسؤول المنشورة تاريخيًا

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

### الهدف

تحديد كل بيئة استُخدمت فيها نسخة المشروع، ثم إثبات أن كلمة مرور المسؤول التي ظهرت تاريخيًا لا تمنح وصولًا،
وأن bootstrap (إنشاء المسؤول الأولي) معطل أو محكوم بإعداد خارجي آمن.

### لماذا هذه أول مهمة؟

لأن الكود أصلح الإنشاء الافتراضي، لكن السر الذي وصل إلى تاريخ Git (نظام تتبع التغييرات) لا يمكن إلغاؤه بتعديل
الكود. إذا كانت هناك بيئة قديمة، فقد يسمح ذلك بوصول إداري قبل أن تفيدنا أي ميزة أو نسخة احتياطية.

### النطاق

- جرد dev/staging/prod (تطوير/اختبار/إنتاج) وأي نسخة تجريبية.
- تحديد حساب المسؤول وحالة lockout/session (القفل/الجلسات) دون تسجيل الأسرار في الوثائق.
- تدوير بيانات الدخول وإبطال الجلسات والمفاتيح ذات الصلة في كل بيئة موجودة.
- التأكد أن bootstrap disabled by default (الإنشاء الأولي معطل افتراضيًا) وأن القيم تأتي من قناة أسرار آمنة.
- حفظ دليل إغلاق خالٍ من الأسرار: البيئة، المالك، الوقت، النتيجة، منفذ التحقق.

### خارج النطاق

- لا تغيير كود أو مخطط قاعدة بيانات.
- لا إعادة كتابة تاريخ Git.
- لا وضع كلمة مرور أو token (رمز وصول) في المستودع.
- لا بدء P0-OPS-002 قبل إغلاق هذه المهمة أو إثبات عدم وجود أي نشر.

### القبول

1. قائمة كاملة بالبيئات ومالك كل منها.
2. السر القديم يفشل في كل بيئة موجودة.
3. كل الجلسات القديمة الحساسة أُبطلت.
4. لا توجد قيم bootstrap فعالة داخل ملفات النشر أو المستودع.
5. دليل مراجعة آمن موقّع من المالك، دون أسرار.
6. تحديث PROJECT_STATUS وNEXT_TASK بعد التحقق.

### الاختبارات

- محاولة دخول سلبية بالقيمة التاريخية من قناة آمنة.
- دخول إيجابي بحساب جديد/مدوّر ثم تحقق الصلاحية الصحيحة فقط.
- تحقق انتهاء الجلسة القديمة وعدم ترقية حساب موجود عبر bootstrap.

### الرجوع

لا تعاد القيمة القديمة. يستخدم إجراء break-glass (وصول طوارئ) موثق ومحدود الزمن إذا فشل الوصول بعد التدوير.
