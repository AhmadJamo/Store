## `MOD-029A` — خط أساس القبول والمصالحة / Acceptance Baseline and Reconciliation Matrix

> الحالة: APPROVED — NEXT INCREMENT ضمن موجة القبول الشامل

اكتمل `MOD-028A..G` وأصبح سجل النقل المولد بصفر أسطح متبقية، مع بقاء MVC هو العرض الافتراضي. تبدأ
`MOD-029A` بتحويل هذا الاكتمال البرمجي إلى baseline قبول قابل لإعادة التشغيل قبل أي تغيير لمسارات العرض.

### الهدف

- إنشاء مصفوفة آلية تربط كل counterpart في السجل بمسار MVC ومسار Angular ونوع القراءة/الكتابة والصلاحيات ودليل الاختبار.
- تشغيل ومصالحة الـdual-run على بيانات Demo نفسها للعينات عالية المخاطر، بدءًا بالمصادقة والجلسة والثقافة ثم المستندات المالية والمخزون.
- تثبيت baseline موحد للبناء والأمان والوصولية والحزم والمتصفح والأداء، وتسجيل أي مانع بيئي صراحة بدل اعتباره نجاحًا.
- إعداد runbook رجوع route-level يستخدم ضوابط cutover الحالية فقط؛ لا تغيير لـpresentation default في هذه الشريحة.

### القبول

- كل counterpart البالغ عددها 82 يظهر مرة واحدة في المصفوفة ولا توجد أسطح أو أدلة مجهولة.
- عينات القراءة تقارن الهوية والحالة والمبالغ/الكميات والأسماء، وعينات الكتابة تستخدم بيانات معزولة أو dry-run ولا تكرر أثرًا ماليًا أو مخزنيًا.
- بوابة القبول الكاملة تمر دون تخطي عندما تكون متطلبات المتصفح/الأداء متاحة؛ أي مانع خارجي موثق مع أمر إعادة تشغيل واضح.
- rollback rehearsal يثبت أن التحويل allowlisted وGET-only وقابل للعكس، مع بقاء MVC افتراضيًا وعدم حذف Razor أو تغيير قاعدة البيانات.
