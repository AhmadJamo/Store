## `P2-SAL-050E / SAL-050` — حجز مخزون طلبات البيع

> الحالة: PROPOSED — AWAITING EXPLICIT APPROVAL

اكتمل `SAL-040`: يتحول عرض السعر المقبول مرة واحدة إلى طلب بيع مستقل بلقطات ثابتة وحالات وتاريخ، ويؤكد الطلب دون أي تغيير في المخزون أو المحاسبة.

### الهدف التالي

ربط طلب البيع المؤكد بنظام `InventoryReservation` (حجز المخزون) الحالي، بحيث تُحجز الكمية المتاحة من مستودع وموقع محددين دون إنقاص الرصيد الفعلي، مع دعم الحجز الكامل أو الجزئي حسب سياسة واضحة، والتحرير وإعادة التخصيص والتزامن.

### الضوابط

- لا يُحجز إلا طلب بيع مؤكد وغير ملغي، ولا تتجاوز الحجوزات كمية السطر المطلوبة بعد طرح المحجوز أو المحرر.
- يختار المستخدم المستودع بالاسم، وتبقى المعرّفات داخلية؛ المواقع والتتبع تتبع سياسات المستودع والمنتج الحالية.
- `Available = OnHand - Reserved` (المتاح = الرصيد الفعلي - المحجوز)، والحجز لا ينقص `OnHand` (الرصيد الفعلي).
- يمنع اختبار قاعدة بيانات متزامن حجز آخر وحدة مرتين.
- سياسة النقص تكون قابلة للتهيئة بوضوح: منع أو حجز جزئي/انتظار، دون إنشاء مخزون سالب ضمنيًا.
- تحرير أو إلغاء الحجز يعيد الكمية المتاحة، مع سجل دلالي وربط الطلب بالمستند الناتج.
- بعد اكتمال الحجز يختفي زر الحجز الكامل وتظهر حالة الحجز والرابط؛ الكمية المتبقية فقط تبقى قابلة للعمل.
- لا ينشئ الحجز قيدًا محاسبيًا؛ التسليم الفعلي يبقى في `SAL-060` (التسليم).

### قبول المرحلة

حجز طلب بيع كامل/جزئي قابل للتدقيق مع اختيار مستودع مسمى، عزل شركة، منع تجاوز الكمية ومنع حجز آخر وحدة مرتين تحت التزامن، وإثبات أن الرصيد الفعلي والمحاسبة لم يتغيرا.

لا يبدأ التنفيذ قبل موافقة المستخدم الصريحة.
