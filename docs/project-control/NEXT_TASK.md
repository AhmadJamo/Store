## `P1-AUD-013` — تدقيق المصادقة والرفض والمنصة والتكامل الخارجي

> الحالة: PROPOSED — AWAITING APPROVAL (مقترحة وتنتظر الموافقة)

> الاعتماد السابق: اكتمل `P1-AUD-012` وربط تغييرات أدوار/صلاحيات الشركة وست مجموعات إعدادات حساسة
> بالحفظ الذري. دليل التنفيذ في
> [operations/P1-AUD-012-SEMANTIC-AUDIT-COVERAGE.md](operations/P1-AUD-012-SEMANTIC-AUDIT-COVERAGE.md).

### الهدف

توسيع `AuditEvent` (حدث التدقيق) إلى الأحداث الأمنية التي لا تمثل تغيير أعمال ناجحًا: محاولات المصادقة
الفاشلة والقفل، رفض العمليات المميزة، إدارة المنصة، وإنشاء/إلغاء وسائل وصول التكامل الخارجي، مع فصل واضح
بين حدث `Succeeded` (نجح) و`Denied/Failed` (مرفوض/فشل).

### داخل النطاق

- اعتماد أكواد ثابتة لفشل تسجيل دخول الشركة والمنصة، القفل، ورفض عملية مميزة مختارة.
- تسجيل إدارة المنصة الحساسة ووسائل وصول المورد/التكامل دون مفتاح أو token (رمز وصول) أو حمولة خام.
- إضافة مسار كتابة أمني مستقل محدود لأحداث الرفض/الفشل بعد انتهاء معاملة الأعمال، مع تنبيه واضح عند فشله.
- تقنيع عنوان المصدر وبصم المتصفح عند الحاجة بدل تخزين القيم الخام، وربط CorrelationId (معرّف الترابط).
- عزل Tenant/Platform/System (الشركة/المنصة/النظام) واختبارات منع الاصطناع والتسرب والتكرار.
- إبقاء مفتاح Demo في User Secrets وتوسيع قوائم السماح للحقول المطلوبة فقط.

### خارج النطاق

- لا شاشة عرض أو تصدير ولا صلاحيات `AuditEvents.*`؛ هذه في `P1-AUD-014`.
- لا تسجيل لكل قراءة عادية أو كل خطأ تحقق من إدخال المستخدم.
- لا تخزين كلمة مرور أو hash (بصمة كلمة المرور) أو cookie (ملف جلسة) أو token أو مفتاح API أو جسم طلب.
- لا إيقاف أو backfill (تعبئة تاريخية) لـ`AuditLogs` القديم.
- لا احتفاظ/أرشفة أو checkpoint (نقطة تثبيت) خارجي؛ هذه في `P1-AUD-015`.

### القبول

1. كل مسار أمني معتمد ينتج حدثًا واحدًا بالنتيجة الصحيحة دون ادعاء تغيير أعمال لم يحدث.
2. فشل المصادقة لا يسرّب اسم مستخدم غير ضروري أو سببًا يساعد المهاجم.
3. مستخدم الشركة لا يستطيع كتابة حدث Platform/System، والمنصة لا تنتحل شركة.
4. أسرار التكامل والطلبات الخام لا تظهر في أي حمولة أو سجل أو دليل اختبار.
5. فشل الكاتب الأمني المستقل ظاهر ومُختبر ولا يُخفى بصمت.
6. إغلاق feature flag (مفتاح التشغيل) يوقف الكتابة الجديدة دون حذف الدليل السابق.
7. البناء واختبارات الأمان وSQL (قاعدة البيانات) ناجحة، والعدد المتوقع للأحداث متطابق.
