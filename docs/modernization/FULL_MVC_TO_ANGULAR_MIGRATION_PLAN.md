# خطة النقل الكامل من MVC إلى Angular

> Status: APPROVED FOR INCREMENTAL EXECUTION  
> Approved: 2026-10-24  
> Target: Angular becomes the only tenant ERP presentation after proven parity and an explicit final cutover  
> Database and business authority: existing Application/Domain/Infrastructure layers

## الهدف الملزم

نقل **كل ما يحتاج المستخدم رؤيته أو تنفيذه** من Razor MVC إلى Angular تدريجيًا. يشمل ذلك صفحات القوائم
والتفاصيل والإنشاء والتعديل، كل الأزرار والإجراءات والحالات، البحث والتصفية والتقسيم، الأخطاء والتزامن،
المرفقات والتنزيلات وPDF، الترجمة العربية/الإنجليزية، RTL/LTR، إرشاد الخطوات والصلاحيات. لا يُحسب نقل HTML
وحده كإنجاز، ولا تُعاد كتابة قواعد الأعمال في Angular.

## قاعدة التصميم

النقل هو **functional parity وليس نسخ شكل MVC**. تُعاد صياغة كل شاشة حسب نظام تصميم Angular المعتمد:

> MVC هو checklist للوظائف والبيانات والإجراءات فقط. الشكل، توزيع العناصر، التنقل، الجداول، البطاقات،
> النوافذ وتجربة الهاتف مصدر حقيقتها هو Angular design system الذي بُني في `MOD-003..016`.

- semantic design tokens والمظهر الفاتح/الداكن والكثافة وملفات مساحة العمل؛
- responsive من الهاتف إلى الشاشات الواسعة، وRTL/LTR كامل باستخدام logical CSS؛
- مكونات Angular المشتركة المثبتة للقوائم والنماذج والحالات والاسترجاع والرحلات والأدلة؛
- hierarchy ومساحات وإجراءات واضحة، keyboard/focus/accessibility وحالات loading/empty/error/skeleton؛
- تخصيص presentation آمن وقابل للتوسعة دون تخزين صلاحيات أو بيانات أعمال في المتصفح؛
- كل CSS/SCSS في ملفات منفصلة، ولا inline CSS داخل HTML؛
- لا يُفرض تخطيط MVC أو Bootstrap القديم إذا كان Angular design يقدم تجربة أوضح، لكن لا يجوز إسقاط وظيفة
  أو إجراء أو معلومة لازمة أثناء إعادة التصميم.
- visual parity مع MVC ليست مطلوبة ولا مرغوبة؛ المطلوب اتساق كامل مع خط Angular وتجربة استخدام أفضل.

تتضمن بوابة المطابقة مراجعتين منفصلتين: `Functional parity` للتأكد من عدم فقدان أي وظيفة، و
`Angular design acceptance` للتأكد من أن الشاشة مبنية بأسلوب Angular المتناسق وليست نسخة Razor.

## تعريف اكتمال أي شاشة

لا تُصنّف الشاشة `Angular Complete` إلا عند تحقق جميع الآتي:

1. جرد كل MVC routes وGET/POST actions والأزرار والنوافذ وJavaScript والتنزيلات المرتبطة بها.
2. API versioned يستخدم DTOs وخدمات Application ولا يصل إلى EF من controller.
3. مطابقة صلاحيات العرض والتنفيذ وtenant isolation وCSRF والتحقق والتزامن.
4. مطابقة الحالات والانتقالات والأرصدة والكميات وروابط المستندات وإخفاء الإجراءات المكتملة.
5. ترجمة `en-US` و`ar-JO` كاملة، RTL/LTR، لوحة مفاتيح، focus، mobile وaccessibility.
6. اجتياز مراجعة Angular design system على الهاتف/اللوحي/سطح المكتب والمظهرين والكثافتين.
7. اختبارات unit/API/E2E لمسار النجاح وvalidation/forbidden/concurrency/retry حيث ينطبق.
8. تشغيل Angular وMVC بالتوازي خلال نافذة تحقق، مع route-level rollback موثق.
9. تحديث كتالوج Workflow ودليل الشاشة وخريطة النقل.

## سجل النقل المركزي

لكل MVC controller/view/action يُحفظ سجل واحد بالحالات:

- `Inventoried`: تم جرد الشاشة وكل إجراءاتها.
- `API Ready`: العقود المحمية مكتملة.
- `Angular Pilot`: Angular يعمل مع بقاء MVC افتراضيًا.
- `Parity Proven`: الوظائف والصلاحيات والترجمة والاختبارات متطابقة.
- `Angular Default`: التوجيه الافتراضي إلى Angular مع rollback.
- `MVC Retired`: أزيل مسار العرض فقط بعد موافقة `MOD-030`.

## ترتيب التنفيذ داخل كل موجة

1. جرد الشاشة والإجراءات والاعتماديات.
2. إعادة استخدام Application service أو إصلاح حدوده قبل API.
3. إنشاء API DTOs وعقود أخطاء وصلاحيات صريحة.
4. إنشاء Angular vertical slice وSCSS خارجي.
5. اختبارات ومطابقة MVC/Angular على نفس البيانات.
6. تفعيل Angular افتراضيًا للوحدة عبر route cutover قابل للعكس.
7. مراقبة نافذة الاستقرار ثم تعليم الوحدة `Parity Proven`.

## ضوابط عدم فقدان الوظائف

- يبقى backend المرجع الوحيد للترقيم والأسعار والضرائب والمخزون والمحاسبة والحالات.
- لا generic CRUD أو generic entity API ولا إرسال أسماء جداول/حقول حرة.
- كل POST في MVC يقابله command API مصرح ومضاد للتكرار/التزامن حسب طبيعة العملية.
- ملفات PDF والتنزيلات تبقى عبر المحركات المركزية وتتحقق من الصلاحية عند كل طلب.
- لا تُحذف صفحات MVC التاريخية أو public/platform قبل وجود بديل واختبار rollback.
- الوظائف غير المستخدمة لا تُحذف ضمن النقل؛ تُرفع كقرار منتج مستقل مع دليل استخدام.

## بوابة الاعتماد النهائي

لا يبدأ `MOD-030` حتى يصبح سجل النقل خاليًا من `Inventoried` و`API Ready` و`Angular Pilot`، وتصبح
كل الوجهات المطلوبة `Parity Proven` أو لها استثناء معتمد. يجب أن تنجح المصالحة المحاسبية والمخزنية،
كل workflows، اختبار الصلاحيات، العربية والإنجليزية، الهواتف، المتصفحات المدعومة، الأداء، النسخ/الاستعادة
وتجربة الرجوع. إزالة MVC قرار أخير منفصل ولا تُستنتج من اكتمال شاشة واحدة.
