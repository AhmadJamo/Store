# خطة قوالب عروض الأسعار المتقدمة

> الحالة: المرحلة الأولى منفذة في المصدر بتاريخ 2026-10-22
> النطاق: SAL-120A قوالب العروض والمنتجات الاختيارية

## القرار التنفيذي

تنفذ الميزة على مراحل مستقلة حتى تبقى قابلة للتخصيص من دون ربط MiniStore مبكرا ببوابة زبون أو مزود توقيع أو دفع محدد. المرحلة الأولى أصبحت أساسا مستقلا لقوالب عروض قابلة للإصدار، وبنود مطلوبة واختيارية وبديلة، ومجموعات خيارات ذات حد أدنى وأقصى، مع إعادة تسعير لحظية للزبون وتجميد اللقطة المطبقة داخل عرض السعر.

لا يخزن القالب سعرا نهائيا. عند استعماله يعيد النظام تقييم السعر والعملة والضريبة حسب الزبون وتاريخ العرض وقائمة الأسعار، ثم يحفظ الدليل التجاري النهائي داخل عرض السعر. هذا يمنع أن تصبح الأسعار القديمة المخزنة في القالب مصدر حقيقة منافسا لمحرك التسعير.

## ما تعلمناه من المنافسين

راجعت المصادر الرسمية التالية، واستعملت النتائج كمدخل تصميم لا كنسخ حرفي:

- Odoo يدعم القوالب القابلة لإعادة الاستخدام، مدة الصلاحية، البنود والأقسام والملاحظات والمنتجات الاختيارية والشروط والقالب الافتراضي. كما يفصل التوقيع والدفع الإلكترونيين كقدرات إضافية. المصدر: https://www.odoo.com/documentation/18.0/applications/sales/sales/sales_quotations/quote_template.html
- Odoo PDF Quote Builder يدعم غلاف العرض والترويسة والتذييل والمستندات الفنية والحقول الديناميكية. احتفظنا بهذه القدرة للمرحلة التالية لأنها تحتاج ملكية مستقلة لعرض المستند والطباعة. المصدر: https://www.odoo.com/documentation/20.0/applications/sales/sales/sales_quotations/pdf_quote_builder.html
- Salesforce CPQ يفصل القالب إلى أقسام ومكونات قابلة لإعادة الترتيب ويعامل إخراج المستند كطبقة مستقلة عن تكوين المنتجات. المصدر: https://help.salesforce.com/s/articleView?id=sf.cpq_quote_templates.htm&language=en_US&type=5
- Salesforce Industries يضيف البحث والوسوم وإدارة دورة حياة القوالب وإعادة استعمال التكوينات. انعكس ذلك في الفئة والوسوم والبحث وحالات المسودة والنشط والمؤرشف والإصدارات غير القابلة للتعديل. المصدر: https://help.salesforce.com/s/articleView?id=ind.comms_cpq_managing_quote_and_order_templates.htm&language=es&type=5
- HubSpot يفصل بين تخطيط القالب والعلامة التجارية وملخص العرض والبنود والشروط والقبول والدفع. لذلك لم نخلط تكوين المنتجات مع بوابة القبول أو تكامل الدفع. المصدر: https://knowledge.hubspot.com/quotes/create-quote-templates?subtype=page_templates

## المرحلة المنفذة SAL-120A

1. إنشاء قالب كمسودة بكود محايد لغويا ورقم إصدار واسم ووصف وفئة ووسوم.
2. نسخ قالب موجود إلى إصدار أعلى مع الاحتفاظ بالكود ومنع رقم إصدار أقل أو مكرر.
3. تفعيل إصدار واحد من الكود وأرشفة الإصدار النشط السابق بدلا من تعديل التاريخ.
4. اختيار قالب افتراضي واحد نشط لكل شركة.
5. تحديد مدة صلاحية عرض السعر وقناة السعر وقائمة أسعار اختيارية.
6. إضافة مقدمة وشروط وأحكام وملاحظات ختامية يعاد استعمالها مع القالب.
7. تنظيم البنود في أقسام مرتبة مع ملاحظات لكل بند.
8. تعريف البند كمطلوب أو اختياري أو بديل.
9. تحديد الاختيار الافتراضي والكمية الافتراضية والحد الأدنى والأقصى.
10. جعل الكمية ثابتة أو قابلة للتعديل حسب البند.
11. جمع البدائل في مجموعات خيارات لها اسم وكود وحد أدنى وأقصى لعدد الاختيارات.
12. السماح أو المنع الصريح لإضافة منتجات خارج القالب.
13. التحقق من أن المنتج فعال وقابل للبيع وأن وحدة البيع فعالة ومن نفس بعد وحدة المخزون.
14. إعادة تسعير البنود المختارة للزبون وتاريخ العرض من خلال محرك الأسعار الحالي.
15. منع العبث بمعرف المنتج أو الوحدة أو الضريبة أو حدود الاختيار عبر طلب HTTP مصطنع.
16. تجميد كود القالب وإصداره واسمه ونصوصه ونوع البند والقسم ومجموعة الخيار داخل عرض السعر.
17. إبقاء البنود غير المختارة خارج العرض النهائي مع حفظ القالب الأصلي مستقلا لإعادة الاستخدام.
18. توفير شاشات عربية وإنجليزية متجاوبة للإدارة والتفعيل والأرشفة والنسخ والتطبيق.
19. فصل صلاحية مشاهدة القوالب عن صلاحية إدارتها، وحماية كل تغييرات POST من CSRF.
20. توجيه المستخدم بعد تفعيل القالب مباشرة إلى إنشاء عرض سعر مع إعادة التسعير.

## خطة المراحل القادمة

### SAL-120B عرض المستند والعلامة التجارية

1. تعريف تصميم عرض مستقل عن قالب المنتجات حتى يمكن تغيير الشكل من دون تغيير قواعد الاختيار.
2. دعم غلاف وشعار وألوان وخطوط وهوامش وترويسة وتذييل قابلة للتخصيص لكل شركة.
3. دعم ترتيب أقسام العرض وإظهار أو إخفاء الأسعار الفرعية والخصم والضريبة.
4. إرفاق صفحات أو مستندات فنية حسب المنتج أو فئة القالب.
5. معاينة PDF ثنائية اللغة مع RTL صحيح واختبارات لقطة بصرية.
6. تجميد إصدار تصميم المستند داخل العرض المرسل حتى لا يتغير مستند تاريخي لاحقا.

### SAL-120C تعاون الزبون

1. رابط آمن محدود المدة لعرض نسخة ثابتة من عرض السعر.
2. اختيار المنتجات الاختيارية والبدائل ضمن الحدود التي حددها القالب.
3. إعادة احتساب المجموع في الخادم وعدم الثقة بحسابات المتصفح.
4. تعليقات وأسئلة ومرفقات مقيدة بالحجم والنوع وسجل أحداث كامل.
5. إصدار مراجعة جديد عند تغيير اختيار الزبون بدلا من الكتابة فوق النسخة المرسلة.
6. قبول أو رفض مع اسم الشخص والوقت وعنوان IP وسياسة الخصوصية المعتمدة.

### SAL-120D التوقيع والدفع

1. اختيار مزود توقيع ومزود دفع بقرار معماري منفصل وموافقة صريحة.
2. حفظ معرف العملية وحالتها ومفاتيح منع التكرار فقط وعدم تخزين أسرار في المستندات أو السجلات.
3. التحقق من توقيع Webhook وإعادة المحاولة الآمنة وحالة تسوية واضحة.
4. منع اعتبار العرض مقبولا أو مدفوعا اعتمادا على واجهة المستخدم وحدها.
5. ربط العربون أو الدفع بكيان تحصيل مستقل وعدم إنشاء قيد أو حركة مخزون من القالب نفسه.

### SAL-120E مكتبة المحتوى والحوكمة

1. مكتبة فقرات وشروط مع إصدار ولغة وتاريخ سريان وموافقة قانونية.
2. صلاحيات أدق للنشر والأرشفة وتعيين الافتراضي.
3. مسار مراجعة للقوالب عالية المخاطر قبل التفعيل.
4. تحليل استعمال القالب ونسب اختيار الخيارات والقبول والزمن حتى القرار.
5. استيراد وتصدير مضبوط للقوالب بعد إضافة معاينة وتحقق وحدود حجم واضحة.

## معايير القبول الحالية

- لا يمكن تطبيق قالب غير نشط أو إصدار مختلف عن الإصدار المطلوب.
- لا يمكن حذف بند مطلوب أو كسر حدود كمية ثابتة أو مجموعة خيارات.
- لا يمكن إضافة بند خارجي عندما يمنع القالب ذلك.
- لا يخزن القالب سعرا نهائيا، ويعاد التسعير عند إنشاء العرض.
- لا يؤدي إنشاء القالب أو تطبيقه إلى مخزون أو حجز أو قيد محاسبي أو دفع.
- القوالب وعناصرها وعروضها معزولة حسب الشركة بعلاقات Tenant مركبة.
- يوجد قالب افتراضي نشط واحد فقط لكل شركة.
- القالب النشط غير قابل للتعديل؛ التغيير يتم بإصدار جديد.

## التحقق والمخاطر المفتوحة

بناء Release وفحوص الانحدار نجحا. نموذج EF مطابق للترحيل 132. سيناريو SQL يغطي حفظ لقطات القالب والعناصر لكنه لم ينفذ لأن اتصال SQL المحلي يتوقف قبل بدء الاختبار بخطأ SSPI. تطبيق الترحيلات 129 حتى 132 على Demo ينتظر إصلاح اتصال المضيف. بوابة الزبون والتوقيع والدفع وPDF المتقدم ليست جزءا من المرحلة الحالية ولا تبدأ بلا موافقة ومزود واضحين.
