# Backup & Disaster Recovery
Classify critical systems: SQL transactional data, control plane, object storage, secrets, configuration, event queues, audit, source/infrastructure manifests. Define and approve RPO/RTO per tier (illustrative target critical financial data RPO <= 15 min, RTO <= 4 h; validate cost and provider capability). SQL full/differential/log backup or managed PITR; geo redundancy by risk; encrypted backups, offsite copies, retention and deletion rules, least-privilege restore.

Runbook: detect incident -> declare severity -> freeze writes as needed -> verify backup integrity -> restore to isolated environment -> replay/verify transactions/outbox -> reconcile ledger and stock -> DNS/routing cutover -> notify tenants -> postmortem. Test restores at least quarterly and after major architecture changes; record actual RPO/RTO and evidence. Tenant-level point-in-time restore in shared DB is NOT trivial: design tenant export/recovery and consistency boundaries separately. Backup is not HA; add failover planning.
